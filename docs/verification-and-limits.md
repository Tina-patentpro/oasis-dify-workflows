## 3. 已知问题（原样保留，不粉饰）

来自源项目与 11-04 发布报告：

1. **DSL schema 版本混杂**：12 份 YML 的 `version` 跨 `0.1.2` ~ `0.6.0`，
   与具体 Dify 版本的兼容程度未知。
2. **候选未指定**：源项目中央登记册把 14 个流程的 `current_candidate_yml` 全部登记为
   `undesignated`，`asset_state` 多为 `legacy_assets_present`，`contract_state` 全部
   `gap_confirmed`，`evidence_status` 全部 `STATIC_ONLY`；登记册原文：
   "现有资产是迁移后的历史实现基线，尚未达到 V3.4.0 目标合同。"
3. **命名沿用**：4-11 / 4-12 的 `app.name` 大量沿用上游 `flow-2-6-` / `flow-2-7-` 前缀，
   与目录编号不一致（历史命名习惯）。
4. **语法损坏（已排除）**：`Flow-3-8` 源 YML 第 249 行
   `type: custom  environment_variables:` 两个键挤在一行，解析失败。按原件保全、
   不擅改 DSL 的原则排除，交 Codex 修正后另版。
5. **无 YML（已排除）**：`Flow-3-9 专利撰写计划` 目录为空，源登记册记 `no_yml`。
6. **发布报告保留的质量问题（未复测修正）**：TRIZ 的构型细节、重复陈述、空衍生章节及
   轻微分页问题；语义生图的图内待确认表达与请求尺寸不符；工作聚焦及 Basic 报告的内容完善项。
7. **未覆盖分支与压力验收**：11-04 报告明确没有把未覆盖分支或 30 万字／900 秒压力验收
   标记通过，也没有为发布重新收费运行。
8. **脱敏静态差异复核已返回（`STATIC_ONLY`）**：对准确固定源／公开字节对的静态差异复核已完成，仅认证请求头标量变化，图结构未变；这不代表 Dify 导入、真实请求或专业／用户接受。原凭据轮换事项仍按原记录处理，本项不声称凭据已撤销，也不验证旧凭据。

## 4. 本次发布实际执行的检查

- 从 `1、专利工作流` 下 14 个流程的 `YML/` 目录中，按 `catalog.json` 的
  `selection_basis` 逐项选取具名版本；**没有**按最高版本号、修改时间或文件数量挑选；
- 严格避开源项目的 `5、存档`（未扫描、未读取）；
- 逐文件计算源 SHA-256 与发布副本 SHA-256，记录字节差异；
- 用 Ruby Psych 做 YAML 语法解析；
- 逐文件敏感内容扫描 + 命中行结构定位；
- 对 1 处真实凭据做精确替换，并登记源 hash → 发布 hash；
- 复制后重算所有发布文件 hash，与 `catalog.json` 一致；
- 文档内的路径、文件名、版本、节点数均从实际资产机械提取后填写。

**未执行**：实例导入、配置绑定、模型/工具调用、运行证据、专业审阅、用户接受、
任何具体 Dify 版本的兼容性测试。

## 6. 使用建议

- 当作**可读的设计参考**，不要当作可交付服务；
- 先在隔离实例、免费检查范围内验证；真实运行需单独明确受测版本、输入、环境与费用范围；
- 不要把已知质量问题写成"全面测试通过"；
- 按 [导入与配置指南](import-guide.md) 的格式提交问题，附资产 ID、版本、准确文件／节点、
  预期与实际、证据路径和影响。
